# رویش — Functional Prototype مدیریت استعداد و جانشین‌پروری

نمونه تعاملی فارسی و RTL بر اساس `Talent_Succession_Prototype_Master_Reference_FA.md`. تمام اشخاص، شواهد و داده‌ها ساختگی‌اند. این نسخه برای ارائه جریان‌هاست؛ محصول عملیاتی، سامانه استخدام یا ابزار روان‌سنجی نیست.

## اجرای سریع

پیش‌نیاز: **Node.js 24.19+** و **pnpm 11.25.0** (نسخه‌های استفاده‌شده برای توسعه).

```bash
pnpm install --frozen-lockfile
pnpm start
```

مرورگر: `http://localhost:4200`. نقش اولیه «کارشناس منابع انسانی» است. همه داده‌ها با اولین اجرا آماده‌اند و API یا سرویس دیگری لازم نیست. فونت Vazirmatn نیز محلی بسته‌بندی شده؛ برنامه هنگام استفاده وابسته به CDN نیست.

```bash
pnpm build
pnpm test
pnpm exec playwright install chromium
pnpm test:e2e
```

خروجی قابل میزبانی استاتیک: `dist/talent/browser`. برای Deep Linkها، میزبان باید مسیرهای ناشناخته را به `index.html` بازنویسی کند. برای عرضه در زیرمسیر، `pnpm exec ng build --base-href /your-path/` اجرا شود. این پروژه هیچ Backend یا دیتابیس واقعی ایجاد نمی‌کند.

## قابلیت‌های قابل استفاده

- **شناسنامه شغلی:** ۱۰ شغل، اطلاعات ۱۱گانه، وظایف خروجی‌محور، KPI با تعریف و منبع یکتا، ویرایش پیش‌نویس، گردش تأیید مالک و تاریخچه نسخه. نسخه منتشرشده تا تأیید تغییر نمی‌کند؛ پس از تأیید، شکاف‌های وابسته به‌روز می‌شوند.
- **مسیر رشد:** رابطه مبدأ/مقصد، ثبت معیار ارتقا و لینک به شغل و تحلیل شکاف.
- **افراد:** ۳۶ فرد ساختگی، جستجو، فیلتر، صفحه‌بندی، پروفایل، سابقه ارزیابی، عملکرد و پتانسیل مستقل.
- **ارزیابی ۳۶۰/۵۴۰:** ایجاد دوره، انتخاب ارزیاب، کنترل حداقل ۱ سرپرست + ۲ هم‌سطح + ۲ زیردست؛ در حالت ۵۴۰ حداقل یک بیرونی به‌عنوان تصمیم دمو. پرسشنامه تألیفی پنج‌شایستگی با لنگر رفتاری ۱–۵، ثبت تکلیف، کالیبراسیون با یادداشت، گزارش راداری، مقایسه دوره پیشین و شکاف.
- **محرمانگی نمایشی:** مدل گزارش فاقد شناسه و نام ارزیابان است. گروه هم‌سطح/زیردست با کمتر از دو پاسخ منتشر نمی‌شود؛ این آستانه تصمیم پیشنهادی دمو است.
- **IDP:** ایجاد سه اقدام از بیشترین شکاف‌ها، مسئول، مهلت، شاخص موفقیت و وضعیت. پیشرفت در پروفایل، فهرست توسعه و داشبورد یکسان است.
- **دانش/AAR:** ۱۸ محتوا، جستجوی عنوان/متن/کلیدواژه/وظیفه، فیلتر وضعیت و موعد بازنگری؛ ایجاد و ویرایش پیش‌نویس، پنج محور AAR و اقدام مسئول‌دار، گردش بازبینی، تأیید مالک، انتشار و بایگانی؛ اتصال به وظیفه شغل و ثبت مشاهده. پیوست TXT/MD تا ۵۰KB داخل مرورگر ذخیره می‌شود.
- **جانشین‌پروری:** ۱۵ پست از جمله ۵ پست حیاتی، نامزدهای مشترک، مقایسه دو/سه نفر، شکاف و IDP؛ آمادگی A/B/C برای رابطه فرد × پست، فقط با ثبت شواهد انسانی.
- **۹ خانه:** انتخاب خانه، فیلتر واحد و لینک پروفایل؛ هیچ انتصاب خودکاری انجام نمی‌شود.
- **داشبورد و گزارش:** نماهای HR/مدیرعامل/واحد، شاخص‌های مشتق‌شده از داده مشترک، نمودار شایستگی، فهرست اقدام‌ها، پست‌های فاقد نامزد آماده، جدول شکاف، خروجی CSV.
- **کنترل دمو:** شش نقش نمایشی، Route Guard و محدودیت UI، ثبت حداکثر ۲۵۰ رویداد، شبیه‌سازی قرارداد داده، بازنشانی با تأیید و بازیابی داده نامعتبر.

## دمو در ۱۰ تا ۱۵ دقیقه

راهنمای گام‌به‌گام: [docs/DEMO.md](docs/DEMO.md). همین راهنما در `/demo/settings` هم در دسترس است.

1. در نقش HR، شناسنامه «مدیر پروژه» را ویرایش و برای تأیید ارسال کنید. نقش را به مالک خانواده شغلی تغییر دهید و تأیید کنید.
2. به HR برگردید، دوره آماده «ارزیابی پاییز ۱۴۰۵» را باز و پاسخ‌گیری را شروع کنید.
3. وارد نقش ارزیاب شوید؛ در انتخابگر شخصیت، هر شش ارزیاب را به‌ترتیب انتخاب و پرسشنامه‌ها را ثبت کنید.
4. در HR، پاسخ‌گیری را ببندید؛ یادداشت کالیبراسیون بنویسید و گزارش را منتشر کنید.
5. از گزارش، IDP بسازید؛ یکی از سه اقدام را انجام‌شده کنید. پیشرفت ۳۳٪ را در برنامه و پروفایل ببینید.
6. در جانشینی پست مدیر پروژه، برای یکی از نامزدها با دلیل انسانی آمادگی A ثبت کنید. پوشش داشبورد تغییر می‌کند.
7. AAR بسازید، ارسال کنید و با نقش مالک منتشر کنید؛ محتوا در شناسنامه شغل هم دیده می‌شود.

## ساختار حداقلی

```text
src/app/core/         مدل‌ها، Seed، توابع محاسباتی، Store مشترک و عملیات دامنه
src/app/features/     صفحات مستقل با Lazy Load در سطح Route
src/app/shared/       قالب‌های مشترک، تاریخ شمسی، خروجی فایل، نمودار Lazy
src/app/app.routes.ts مسیرها و کنترل نقش نمایشی
src/app/app.ts        پوسته و انتخاب نقش
```

Angular 22.2.3، Standalone، Signals و حالت پیش‌فرض Zoneless؛ Angular Material برای دکمه‌ها، تب‌ها و Progress؛ فرم‌های سبک با FormsModule؛ TypeScript Strict؛ ApexCharts فقط با dynamic import و `@defer`؛ pnpm و lockfile ثبت‌شده.

`Store` یک سرویس مستقیم و کوچک است؛ State فقط از طریق عملیات نام‌دار تغییر می‌کند. رابط‌های مدل در `models.ts` و محاسبات مستقل در `domain.ts` هستند. لایه‌های CQRS، NgRx، Repositoryهای تکراری و Backend اضافه نشده‌اند. برای محصول واقعی، می‌توان پشت این عملیات API قرار داد و کنترل دسترسی را سمت سرور پیاده کرد.

## قواعد و محدودیت‌های شفاف

- تنها شرح خدمات و پیوست‌ها مبنای الزام‌اند؛ A/B/C، ۹ خانه و ریسک از مرجع آموزشی‌اند. GIA اجرا یا بازتولید نشده است.
- میانگین ساده گروه‌های قابل انتشار، شکاف `max(0, expected-observed)` و نسبت تعداد اقدام‌های کامل، **فرمول پیشنهادی دمو** هستند.
- فیلتر دوره روی ارزیابی و IDP اثر دارد. شناسنامه، دانش و جانشینی وضعیت فعلی هستند و در UI همین موضوع ذکر شده است. نمودار سطح شایستگی از آخرین گزارش منتشرشده یا شواهد اولیه می‌آید.
- تأیید کالیبراسیون نمره خام را تغییر نمی‌دهد؛ نظر بررسی‌کننده را ثبت و گزارش را قابل انتشار می‌کند. دوره تنها پس از تکمیل همه تکالیف بسته می‌شود؛ استثنای کمبود ارزیاب پیاده نشده است.
- پوشش شناسنامه در Seed برابر ۱۰۰٪ است چون تمام مشاغل نسخه منتشرشده دارند؛ ویرایش‌ها پیش‌نویس نسخه بعدی‌اند.
- تاریخ در مدل ISO/Gregorian است و در نماها با `Intl.DateTimeFormat('fa-IR')` شمسی نمایش داده می‌شود. کنترل انتخاب تاریخ native مرورگر میلادی است و برچسب آن صریح است.
- LocalStorage نسخه‌دار با کلید `royesh.demo.v1`؛ تغییرات همان مرورگر باقی می‌مانند. Role/شخصیت انتخابی پس از Reload به نقش اولیه برمی‌گردد. خطای ذخیره‌سازی با پیام مشخص می‌شود و State حافظه ادامه می‌یابد.
- انتخاب نقش و Guardها **امنیت یا احراز هویت واقعی نیستند**؛ داده واقعی کارکنان را وارد نکنید. همکاری چندکاربره، همگام‌سازی بین دستگاه‌ها و اتصال واقعی HR/ETL خارج از نسخه‌اند.
- شاخص توسعه معادل اثربخشی قطعی آموزش نیست؛ امتیاز آزمون و ۹ خانه مبنای انحصاری تصمیم استخدام یا جانشینی نیستند.
