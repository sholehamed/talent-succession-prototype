# رویش | سامانه مدیریت استعداد و جانشین‌پروری

**رویش** یک سامانه فارسی، راست‌به‌چپ و تعاملی برای مدیریت شناسنامه‌های شغلی، مسیرهای رشد، ارزیابی چندمنبعی، توسعه فردی، مدیریت دانش و جانشین‌پروری است.

این مخزن وضعیت **جاری توسعه** را دربر دارد: ماژول‌ها و گردش‌کارهای اصلی در Frontend قابل استفاده‌اند و داده‌های مرتبط در یک Store مشترک نگهداری می‌شوند؛ سرویس Backend، پایگاه داده سازمانی و احراز هویت سمت سرور هنوز به این نسخه متصل نیستند. برای بررسی سامانه از داده‌های غیرواقعی استفاده شده است.

## اجرا

پیش‌نیاز: Node.js نسخه ۲۴.۱۹ یا بالاتر و pnpm نسخه ۱۱.۲۵.

```bash
pnpm install --frozen-lockfile
pnpm start
```

آدرس: `http://127.0.0.1:4200`

```bash
pnpm build
pnpm test
pnpm exec playwright install chromium
pnpm test:e2e
```

خروجی Production: `dist/talent/browser`. برای میزبانی SPA، درخواست‌های ناشناخته مسیر باید به `index.html` هدایت شوند. فونت Vazirmatn در خود برنامه بسته‌بندی می‌شود.

## ناوبری سامانه

منوی اصلی به هفت گروه بازشونده با آیکن‌های رسمی Material به‌صورت SVG آفلاین تقسیم شده است؛ در هر لحظه فقط یک گروه باز می‌ماند، گروه مرتبط با صفحه فعال خودکار باز می‌شود و دسترسی نقش‌های فعلی محفوظ است. تنظیمات در پایین سایدبار قرار دارد. [راهنمای سایدبار](docs/SIDEBAR_NAVIGATION_FA.md).

داشبورد اصلی هر نقش مدیریتی مستقل است و در سایدبار فقط همان داشبورد نمایش داده می‌شود؛ گزارش‌های مدیریتی و داشبورد توسعه همچنان مشترک‌اند. [روند دقیق داشبوردهای نقش‌محور](docs/ROLE_DASHBOARD_NAVIGATION_FA.md).

## قابلیت‌های فعلی

**مدیریت نقش‌های کاربران:** در نسخه فعلی، منابع انسانی می‌تواند نقش‌های موجود را از مسیر `/access/roles` به اشخاص اختصاص دهد یا لغو کند؛ شناسه‌های ثابت قبلی دیگر مرجع مجوز نیستند. [راهنمای مدیریت دسترسی](docs/ROLE_ACCESS_MANAGEMENT_FA.md).

### اصول داده و تصمیم‌گیری

- **تاریخ در UI شمسی** است؛ مقدار تاریخِ روز در Store به‌صورت `YYYY-MM-DD` میلادی نگهداری می‌شود. تقویم Material از Adapter جلالی استفاده می‌کند.
- انتصاب جاری فرد از پست سازمانی و پست بالاسری استخراج می‌شود؛ در **استخدام جدید انتخاب پست فعال و بلاتصدی موجود الزامی است** و مدیر مستقیماً از چارت تعیین می‌شود، نه از ورودی جداگانه. پست‌های جانشینی و گزارش‌های قدیمی ID خود را حفظ می‌کنند. مراحل ساخت، انتقال و Migration در [راهنمای تشکیلات](docs/ORGANIZATIONAL_STRUCTURE_FA.md) توضیح داده شده است.
- برنامه توسعه حاصل از گزارش به همان دوره ارزیابی متصل است و یک نسخه مستقل برای آن ایجاد می‌شود؛ برنامه‌های قدیمی و پیشرفت آن‌ها حفظ می‌شوند.
- «تکمیل اقدام»، «نظر مدیر درباره اثربخشی» و «رشد شایستگی در ارزیابی‌های متوالی» سه مفهوم جدا هستند؛ مقایسه دوره‌ها، رابطه علّی با اقدامات را اثبات نمی‌کند.
- عملیات سامانه روی داده‌های مشترک اثر می‌گذارند؛ مثلاً انتشار شناسنامه سطح انتظار را تغییر می‌دهد و ثبت نظر جانشینی بر پوشش پست‌های حیاتی در داشبورد اثر می‌گذارد.
- نمایش گزارش چندمنبعی، هویت ارزیابان را در خروجی تجمیعی آشکار نمی‌کند؛ این موضوع جایگزین حفاظت داده در Backend نیست.
- شاخص‌ها و نتایج ارزیابی **اطلاعات پشتیبان تصمیم انسانی‌اند** و انتصاب خودکار انجام نمی‌شود.
- State در LocalStorage با کلید فعلی `royesh.demo.v1` حفظ می‌شود. این کلید برای سازگاری نسخه‌ای نگه داشته شده و نام آن در UI نمایش داده نمی‌شود.
- انتخاب نقش در نوار ابزار برای بررسی گردش‌کارهای موجود است؛ **Authentication و RBAC واقعی** هنوز سمت سرور پیاده‌سازی نشده‌اند. داده واقعی یا محرمانه کارکنان را در این نسخه وارد نکنید.
- تبادل داده منابع انسانی در تنظیمات فعلاً **محلی** است و درخواست واقعی به سرویس سازمانی ارسال نمی‌کند.

## فناوری و ساختار

Angular 22، Standalone Components، Signals، Angular Material، ApexCharts، TypeScript، RTL، pnpm و Playwright.

```text
src/app/core/         مدل دامنه، محاسبات، داده‌های اولیه و Store
src/app/features/     صفحات قابلیت‌ها با بارگذاری در سطح Route
src/app/shared/       DateField، JalaliDateAdapter، نمودار و ابزارهای مشترک
src/app/app.routes.ts مسیرها و Guardهای مبتنی بر نقش
src/app/app.ts        پوسته و ناوبری سامانه
tests/                تست واحد و سناریوهای مرورگری
docs/                 محدوده، راهنمای داخلی ارائه و ردیابی تست
```

در وضعیت فعلی از Backend و پایگاه داده واقعی استفاده نشده است؛ اتصال سرویس و پیاده‌سازی مجوزها در سمت سرور از گام‌های توسعه بعدی خواهند بود.
